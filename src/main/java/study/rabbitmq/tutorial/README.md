## RabbitMQ 튜토리얼
RabbitMQ는 바이너리 데이터 덩어리( 메시지)를 수신, 저장 및 전달하는 메시지 브로커입니다.<br/>
기본 포트는 5672를 사용합니다.<br/>
메시지를 생산해서 보내는것을 Producer(생산자)라고 칭합니다.<br/>
큐는 RabbitMQ에서 메시지를 저장하는 저장소를 의미합니다.
메시지는 RabbitMQ와 애플리케이션을 통해 흐르지만, 실제로는 큐 안에만 저장될 수 있습니다.<br/>
큐는 호스트의 메모리 및 디스크 용량에 따라 저장 용량이 제한되고 기본적으로는 대용량 메시지 버퍼와 같습니다. <br/>
생산된 메시지를 소비하는것은 Consumer(소비자)라고 칭합니다.<br/>

### 순환식 배송
작업량이 쌓이면 작업을 처리할 워커를 추가하기만 하면 쉽게 확장할 수 있습니다.<br/>
기본적으로 RabbitMQ는 메시지를 순서대로 다음 컨슈머에게 전송합니다. 평균적으로 모든 컨슈머는 동일한 수의 메시지를 받게 됩니다.
이러한 메시지 분산 방식을 라운드 로빈이라고 합니다.<br/>

### 메시지 확인
RabbitMQ는 메시지 손실을 방지하기 위해 메시지 확인 응답을 지원합니다.
확인 응답은 컨슈머가 특정 메시지를 수신 및 처리했으면 RabbitMQ가 해당 메시지를 삭제해도 된다는것을 알리기 위해 RabbitMQ에 보내는것입니다.<br/>
컨슈머가 Ack를 보내지 않고 종료되면(채널이 닫히거나, 연결이 끊어지거나, TCP 연결이 손실되는 경우) RabbitMQ는 메시지가 완전히 처리되지 않았다고 판단하고 해당 메시지를 다시 큐에 추가합니다.<br/>
컨슈머가 여러개일 경우 RabbitMQ는 해당 메시지를 다른 컨슈머에게 신속하게 재전송합니다. 워커가 종료되더라도 메시지 손실이 발생하지 않습니다.<br/>
기본적으로 컨슈머가 메시지를 수신하면 시간제한(기본값 30분)이 적용됩니다. 시간 제한으로 수신 확인을 보내지 않는 버그가 있는 컨슈머를 감지하는데 도움이 될 수 있습니다.<br/>
(참고 : 시간 제한을 설정할 수 있는데 해당 방법은 다른곳에서 자세히 다루겠습니다. [시간제한 설정하는 방법](https://www.rabbitmq.com/docs/consumers#acknowledgement-timeout))<br/>
수동 메시지 확인은 기본적으로 활성화되어 있습니다.
autoAck의 기본 설정값은 false라서 수동으로 RabbitMQ에게 메시지 확인했다라는 알림을 보내야하는데 해당 값을 true로 보내면 워커가 작업이 끝나면 자동으로 RabbitMQ에서 메시지 수신 완료 상태값을 보냅니다.<br/>
```java
channel.basicQos(1);
```
위 명령어는 한 번에 하나의 ack(확인 응답)되지 않은 메시지만 수신합니다.<br/>
작업자가 종료된 후 승인 되지 않은 모든 메시지가 다시 전송하기 때문에 데이터 손실이 발생하지 않을 수 있습니다.<br/>
수신 확인은 전달된 메시지와 동일한 채널을 통해 전송이 되어야 하지 다른 채널을 사용하여 수신확인을 시도하면 채널 수준 프로토콜 예외가 발생합니다.
클라이언트가 종료되면 메시지가 다시 전송되지만 RabbitMQ는 승인되지 않은 메시지를 해제할 수 없어서 많은 메모리를 사용하게 됩니다.


### 메시지 지속성
RabbitMQ가 종료되거나 충돌하면 특별히 지정하지 않으면 큐와 메시지가 잊어벌비니다.<br/>
메시지 손실을 방지하려면 아래와 같이 두가지가 필요합니다.<br/>
- 큐와 메시지 모두를 영구 보존(durable)으로 표시해야합니다.
- 메시지 발행 시점에 `MessageProperties`를 `PERSISTENT_TEXT_PLAN` 값으로 설정
아래 명령어를 통해 큐가 RabbitMQ 노드 재시작후에도 유지되도록 할 수 있습니다.
```java
boolean durable = true;
channel.queueDeclare("큐이름",durable, false,false,null);
```
기존에 설정 되어있던 큐에 다른 매개변수로 재정의하는것을 허용하지 않기 때문에 적용하려고 하면 프로그램 오류가 발생할 수 있습니다.
다른 이름의 큐를 새롭게 생성해서 적용하면 문제 없이 적용할 수 있습니다.<br/>
이제 `MessageProperties`를 `PERSISTENT_TEXT_PLAN` 값으로 설정하여 영구 저장 메시지로 표시해야합니다.<br/>
메시지를 영구 저장으로 표시한다고 해서 메시지 손실 방지가 안될 수 있습니다.<br/>
RabbitMQ에 메시지를 디스크에 저장하도록 지시하지만 RabbitMQ가 메시지를 수락한 후 저장하지 않은 짧은 시간 간격이 존재합니다.<br/>
설정값에 따라 모든 메시지를 디스크에 저장하는것이 아니고 캐시에만 저장하는 경우도 있습니다. 따라서 영구 저장 보장이 되지 않습니다.

### 공정한 배송
두 개의 워커가 있는 상황에서 첫번째 워커가 처리량이 많고 두번째 워커가 처리량이 적다면 하나의 워커에서 바쁘게 작동하고 다른 워커에서는 작업을 거의 하지 않게 됩니다. <br/>
RabbitMQ는 이런 상왈을 인식하지 못하고 메시지를 균등하게 디스패칭 합니다.<br/>
이러한 현상이 발생하는 이유는 RabbitMQ가 큐에 메시지가 들어오면 메시지를 소비하고 있는 소비자의 수신 확인하지 않은 메시지 수를 확인하지 않고 무작위로 전송하기 때문입니다. <br/>
이러한 문제를 해결하기 위해서  `basicQos` 방법을 사용할 수 있습니다.<br/>
이렇게 하면 RabbitMQ가 이전 메시지를 처리하고 승인할때까지 새로운 메시지를 워커에 보내지 않습니다.
